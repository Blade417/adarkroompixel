# 聚落兽袭与村民伤亡核查

用户在自己的浏览器打开 5496，停留聚落时经历一次彩蛋与三次兽袭，要求检查抽取和人口损失。个人浏览器与内置浏览器不共享存档；内置浏览器的零人口探索 QA 档不代表用户的村庄。本轮没有读取或覆盖用户个人浏览器的存档，也没有当时四次抽取的完整历史，因此不对其具体候选池作断言。

## 事件抽取

当前核心按原版 `isAvailable()` 筛选，再从合格项等概率抽取，没有防连续重复机制。生火间访客与近林/聚落事件属于不同条件池；近林与聚落共同对应原版 Outside。

| 原版村外事件 | 关键条件 |
| --- | --- |
| 遭破坏的陷阱 | 拥有至少 1 个陷阱 |
| 小屋失火 | 有小屋，人口 > 50 |
| 村中病患 | 人口 > 10 且 < 50，库存有药 |
| 瘟疫 | 人口 > 50，库存有药 |
| 兽群袭击 | 人口 > 0 |
| 武装袭击 | 人口 > 0，已清理城市 |

全局窃贼事件另需窃贼状态，Penrose 彩蛋另有标记。选择接受彩蛋会写入完成标记；选择忽略不写入，因此后者仍可能再次出现。

在人口 1–50、无陷阱/药品、未清城/无窃贼且彩蛋已标记的聚落，唯一候选就是兽袭。此时每次抽到兽袭的概率是 100%，不是随机数卡住。若当时只有彩蛋和兽袭两项候选且保持不变，接下来连出三次兽袭的条件概率为 1/8；拥有其他合格事件时应按实际候选数计算。

专项测试用原内容与真实 `triggerEvent()` 复现一次接受的彩蛋后连续三次兽袭，随机值依次变化；未改写内容或强制指定三次兽袭。兽袭消灭全部居民后将失去可用资格，直到新住户到来。

## 人口与岗位

兽袭在场景首次载入时随机请求扣除 1–10 人，实际损失以现有人口为限，最低为 0。扣人不会拆小屋。采木者是总人口扣除专业工人的余数；伤亡先减少这部分，不足时按原存档岗位顺序减少专业人数，立即重算相应产出。这个模型没有逐个居民的独立身份或永久家庭分配。

事件结束不会再次扣人；自动存档恢复已扣除的人口和岗位。非探索的普通事件弹窗本身不在读档时恢复，但其已经生效的伤亡和奖励不会重新执行。房屋空位保留，后续按原有到来计时补充新住户，所以阅读事件后再看人数，可能已出现人口回升；新住户成为采木者，不会自动恢复死去的专业岗位。

## 验证

新增 `tests/village-casualties.test.ts` 的 12 项回归检查，覆盖上述候选池、变化随机值下的连续兽袭、伤亡 1/5/10 人、超额扣人、全灭后岗位/收入归零、岗位扣减顺序、126 组人口/伤亡边界组合、住房显示合计、读档及新住户到来。与本地原版审计源码的抽取和 `killVillagers()` 对照一致。

独立生产预览 5497 通过设置导入正常聚落准备档：12 人，3 间小屋，采木者 3、猎人 6、制革工 3。用可见调试菜单启动一次兽袭，以隔离实际扣人与 UI，不把这一步当作自然抽取概率验证。

- 弹窗显示居民 −4、毛皮 +100、生肉 +100、牙齿 +10。
- 关闭弹窗后聚落为 8/12 人：采木者 0、猎人 5、制革工 3，小屋仍为 3；猎人每 10 秒产出毛皮/生肉各 2.5。
- 可见设置导出核对以上人数、岗位和收入；没有重复扣减。
- 后续确有新住户补充，人数回升至 10；立即导出并刷新，再从标题页导出，刷新前后人口均为 10，岗位均为猎人 5、制革工 3、设陷者 0。此次回升是新住户，不是伤亡回滚。
- 最终页面警告/错误为 0；临时验收标签页检查后关闭。

`npm run check`：27 个测试文件、227 项测试通过；`npm run build` 与 `git diff --check` 通过。

证据：[兽袭弹窗](playtest/2026-10-17-village-events/01-beast-casualty.jpg)、[袭击后可见导出](playtest/2026-10-17-village-events/after-attack-export.json)、[刷新前后](playtest/2026-10-17-village-events/reload-proof.json)。准备档可由 `node scripts/create-village-event-playtest.mjs` 重建，生产不会加载。

结论：当前检查未发现重复扣人、负人口持久化、岗位超过人口或死亡岗位继续产出的错误。连续兽袭在原版条件筛选下确实可能成为常态，属于早期候选池与体验问题。本轮增加验证，保留原版概率、伤亡范围和岗位处理规则。
