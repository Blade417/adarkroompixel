# 第九阶段：早期探索场景与敌人

按完成度评估的后续顺序，补齐废屋、洞穴、铁矿、前哨的地图图标和地点画面，以及占屋者、普通野兽、洞蜥、蜥蜴、母兽。原版内容脚本与核心数值不变。

## 接入方式

- [v3 素材包](../../assets/pixel/expedition/v3/README.md) 包含四地标图集、五敌人三姿态图集、废屋/洞穴/铁矿三个内景；提示词、生成源图、真实 alpha、SHA-256、实测裁取、逻辑尺寸均留存。
- 地图揭雾之后显示图标；已访问淡化并保留标记，未精修的深区继续显示原字符。地图行为、碰撞、揭雾和移动规则不变。
- 地点入口用森林背景加独立入口物件；进入后换室内环境。前哨复用森林与帐篷物件，没有新增前哨整张背景。
- 当前活动事件的原版定义决定环境，不使用敌人的野外类型覆盖环境，也不因随机遇敌站在已访问地标上而误入室内。洞穴清空转前哨时，正在阅读的洞穴结尾继续显示洞穴；离开后回地图。
- 待机/攻击/受击复用现有战斗时钟和命中通知，武器维持独立分层；读取存档恢复同一事件即可恢复对应场景，不增加存档字段或再次执行 onLoad。
- 地点文字移到画面下方，保持画布位置稳定。720 高度桌面使用 480×270 CSS 画面，为事件选项和武器操作保留空间；画布底层仍为 576×324 逻辑场景。

## 自动与实机验收

`npm run check`：26 个测试文件、215 项测试通过。`npm run build` 和 `git diff --check` 通过。新增 10 项检查覆盖：四个真实地点的入口/内景、普通随机战斗不误入室内、读档不重复扣火把、洞穴转前哨仍保留正在阅读的洞穴现场、已访问图标、PNG 散列/透明比例/裁取比例，以及三地点全部静态敌人的三姿态覆盖。

验收使用独立来源 `127.0.0.1:5496`；合成准备存档由 `node scripts/create-expedition-sites-playtest.mjs` 经真实核心生成，再通过可见设置导入。四个地标放在村旁，周边预先揭雾，带有装备与补给；洞蜥/蜥蜴/野兽额外准备指定分支快照，减少随机分支的重复等待。这些文件不进入生产启动流程，也不代表从新档自然发展。
