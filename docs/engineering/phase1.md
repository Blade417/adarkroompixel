## 3. 结构

| 路径 | 内容 |

| 文件 | 职责 |
|---|---|

| `resample.ts` | 高分辨率原图 → 逻辑像素的缩小算法（纯函数） |
| `artpack.ts` | 读取 manifest 与 PNG，按帧烘焙 |
| `assets.ts` | 汇总画面所需的一切：交付素材、派生帧、程序占位、加载失败时的回退 |
| `standins.ts` | 程序占位与回退图（不取自概念图） |

| `lighting.ts` | 光照图、温度色调、暖光、闪烁 |
| `particles.ts` | 火星与窗外雪；它们只随时间变化、没有内部状态，暂停后恢复也不会错位 |
| `arrival.ts` | 陌生人到来的时间线与触发判断 |
| `fit.ts` | 整数缩放、显示模式、指针坐标换算 |
| `renderer.ts` | 按固定顺序合成一帧 |

启动顺序（`main.ts`）：

1. 读取偏好与存档，建立核心 `Game`、音频与界面。此时显示标题，房间是存档里的状态，时钟尚未走动。
2. `loadSceneArt()` 下载并烘焙素材，然后建立 `Renderer`。

### 4.2 烘焙

- **一次性**
  - 启动时，每个 manifest 帧的 `sourceRect` 被缩小到四舍五入后的 `drawSize`（逻辑像素）。
  - 之后按 1:1 绘制：绘制时从不缩放，也不会把整张图当作一张图来缩放。
- **算法**（`?sample=`）

  | 算法 | 每个逻辑像素的取色 | 效果 |
  |---|---|---|
  | `mode`（默认） | 所覆盖源区域中占比最多的颜色 | 边缘清楚，保持色板，不受源图像素间杂色影响 |
  | `box` | 按透明度加权的平均色 | 颜色准，但偏软 |
  | `nearest` | 区域中心的源像素 | 清楚，但噪点多 |

- **硬边**：精灵的透明度在覆盖率 0.5 处一分为二，结果只有全透明和全不透明，没有半透明毛边（`ALPHA_CUT`）。背景不做这一步。
- **火焰分级**

  | 火力等级 | 处理 |
  |---|---|
  | 0 | 不显示 |
  | 1（余火） | 取第 3 帧压扁：宽 0.6、高 0.18、不透明度 0.75 |
  | 2 / 3 / 4 | 按 0.55 / 0.8 / 1 倍各自烘焙一套 4 帧，8 fps |

  缩放都在烘焙时完成，锚点固定在底部中心。
- **容错**：每件素材单独加载。失败只影响它自己：改用回退图，并在控制台给出警告。

### 4.3 体积

- 六张原图共约 4.9 MB，每次启动时下载，再在浏览器内烘焙。
- 本机预览从加载到首帧约 0.35–0.4 秒；在真实网络上，下载时间会占大头。
- 发布前可以在构建时预烘焙成逻辑尺寸的 PNG。这样不改动美术源文件，体积也能大幅下降（见第 13 节）。

## 7. 绘制顺序

每帧先在 480×270 的离屏画布上合成，再按整数倍（窄屏时先裁切）复制到页面画布，关闭平滑。

1. 底色、房屋背景
2. 窗外雪（裁在窗格内）、窗上霜
3. 到来动画中开门时：门洞夜色与飘雪
4. 门（0 关、1 半开、2 全开）
5. 火炉、柴堆、毛皮堆、人物
6. 光照层，依次为：
   - 光照图（正片叠底）
   - 温度色调（正片叠底）
   - 门缝冷风光（仅到来动画中）
   - 暖光（滤色）
7. 火焰：自发光，画在光照之上，不会被压暗
8. 火星、火炉悬停描边、调试锚点

**与交接建议的差异**

交接建议的顺序是“人物 → 火焰 → 受限暖光覆盖 → 前景梁柱”，这里把压暗和暖光放在了火焰之前：

- 火焰本身就是光源。放在正片叠底之下会被压暗，放在滤色之下又会被冲淡。
- 暖光仍然只照亮火炉周围。

另有两点未定：

- 前景梁柱 `room-front.png` 还没有交付。接入时需要决定它和光照的先后：前景应当受光照影响，但不能被火焰盖住。
- 程序烟已经移除，目前只有火星和窗外雪。

## 9. 陌生人到来

**何时播放**

- 只在游戏进行中、亲眼看到陌生人等级从 0 变为 1 时播放一次。

## 10. 缩放与界面布局

### 10.1 整数缩放

- **整数倍**
  - 缩放倍数 scale 以设备像素计，是整数：不论 DPR 是多少，每个逻辑像素都正好覆盖 scale × scale 个物理像素。
  - 画布后备尺寸 = 取景 × scale，CSS 尺寸 = 后备尺寸 ÷ DPR。
  - 画布在页面上的位置也吸附到设备像素。
- **ps** = scale ÷ DPR，即一个逻辑像素占多少 CSS 像素。
- **显示模式**

  | 模式 | 何时使用 | 取景 |
  |---|---|---|
  | 覆盖 | 完整 480×270 能达到 ps ≥ 2，且可用区域宽高比 ≥ 1.2 | 完整画面 |
  | 堆叠 | 其他情况 | `NARROW_CROP`（480×224），高度最多占视口的 58% |

- **DPR 变化**（浏览器缩放、拖到另一块屏幕）：每帧比较 `devicePixelRatio`，有变化就重新布局。原因见 12.4。

### 10.2 界面布局

| 模式 | 条件 | 摆放 |
|---|---|---|
| side | 覆盖模式，画面左右留白都 ≥ 176 CSS px | 日志在左、库存在右，都从顶部暗带下方开始；生火控件放在地板下的暗带 |
| band | 覆盖模式，留白不足 | 日志、生火控件、库存共用地板下的暗带 |
| stacked | 堆叠模式 | 画面在上，界面在下方依次排列 |

- **顶栏**：高 56 CSS px。它是 4 的倍数，所以在 1.25 / 1.5 / 1.75 倍下仍然落在设备像素上。
- **保护区**
  - 逻辑行 16–216 不允许界面覆盖。这一段从顶部暗带一直到最靠下的落地点，火炉和人物都在其中。
  - 生火控件可以从暗带往上升，但不会超过第 216 行。
  - `tests/pixel.test.ts` 在 7 种 DPR 和约 1.9 万种视口组合上检查了这一点。
- **库存**：band 模式用容器查询，高度 ≤ 103 px 时换成紧凑行。8 种物品也能放下。
- **日志**：最新的在上，较旧的逐级变淡。超出区域的部分在底部 16 px 渐隐，不会被硬切成半行。
- **CSS 变量**：`--cx --cy --cw --ch --room-top --band --bandh`，由 `src/ui/layout.ts` 计算。

## 11. 交互、存档与切页

### 11.1 交互

- 生火与添柴直接点击炉膛，F 键与热区执行同一个 `hud.tend()` 意图，共用核心的 10 秒冷却。
- `HEARTH_TARGET` 覆盖炉口及炉沿，包含炉口内部的透明像素；透明 HTML button 按 `Fit` 的裁切、缩放与位移贴合场景。画面下方的文字操作条已移除。
- 首次进入的短暂引导、悬停/键盘聚焦的动作及消耗、点击结果与拒绝信息均位于炉边。炉台下方只有一条冷却细线，空闲时隐藏。
- 正常状态没有按钮底色和边框；键盘聚焦保留可辨识的焦点，屏幕阅读器可读动作、消耗和拒绝原因。开始游戏时焦点进入场景，不自动显示炉膛按钮外框。
- 到来动画期间点击炉口或空地只跳过动画，不会顺便添柴。弹窗期间场景 inert，F 不会穿透设置或替事件添柴。
- `OpeningProgress` 使用游戏时钟，在恢复状态（3）和温度至少 3 持续 12 秒后调用幂等的 `Room.offerHelp()`；事件未处理时延后推进。原作核心的回房间行为继续调用相同方法。

### 11.2 规则要点

以下规则来自核心，与原作一致。

| 规则 | 说明 |
|---|---|
| 生火 | 消耗 5 块木头；木头未定义时（游戏开头）免费。生火后火力为 3 |
| 添柴 | 消耗 1 块，火力 +1（最高 4）；木头为 0 时拒绝 |
| 火力衰减 | 每 5 分钟降 1 级 |
| 温度 | 每 30 秒向火力靠拢 1 级 |
| 陌生人 0 | 第一次生火后，等级立即从 -1 变为 0 |
| 陌生人 0→1 | 30 秒后到来 |
| 陌生人 1→2→3 | 每 30 秒检查一次，温度 ≥ 3 时升 1 级 |
| 陌生人 3→4 | 像素版在温暖房间内恢复 12 秒后自然推进；原作回到房间时的行为保留 |

### 11.3 存档与切页

- **存储键**：存档 `emberveil.pixel.save`（版本 1.3），设备偏好 `emberveil.pixel.prefs`（语言、声音、音量、动态效果）。
- **保存时机**：核心按自己的节奏保存；另外在页面隐藏（`visibilitychange`）和 `pagehide` 时立即保存。
- **标题**：没有存档时显示“开始”，有存档时显示“继续”。点击后时钟才开始走，并解锁音频。
- **切页返回**
  - 页面在后台时浏览器会暂停主循环。回来后，若一帧的间隔超过 1 秒，就按 1 秒的步长补跑游戏时钟（最多 8 小时），不播放动画。
  - 这期间如果陌生人到了，回来时直接显示蜷缩，不重播进门。
- **读档**：静态恢复，不重播到来。

### 11.4 音频

- **地址**：`BASE_URL` 加文件名。`original/audio` 是 Vite 的静态目录，构建后 86 个 flac 文件位于 `dist/` 根目录。
- **混音**：沿用原作规则。
  - 背景音乐循环，切换时 1 秒交叉淡入淡出。
  - 事件音乐 2 秒淡入，同时把背景音乐压到 20%。
  - 同一个音效还没播完时不重播。

### 12.4 本轮修复的问题

以下问题都是浏览器检查发现的。

| 问题 | 修复 |
|---|---|
| 堆叠模式下，界面因 flex 收缩与画面重叠 | 改为 `flex: none` |
| 没有图标，`/favicon.ico` 返回 404 | 临时用 `data:` 图标 |
| band 模式库存放不下 8 种物品 | 容器查询，换成紧凑行 |
| 日志超出区域时被硬切成半行 | 底部 16 px 渐隐 |
| 冷却中再点时状态文字不高亮 | 见下方说明 1 |
| 只改变 DPR 时不重新布局 | 见下方说明 2 |

1. **冷却高亮**：拒绝文字与等待文字相同，而旧代码只在文字变化时切换高亮。现在高亮状态单独记录。
2. **DPR 变化**：模拟器和部分浏览器在只改 DPR 时既不触发 `resize`，也不触发 `matchMedia` 变化（Safari 16 之前不支持 `resolution` 媒体特性）。现在改为每帧比较 DPR。
