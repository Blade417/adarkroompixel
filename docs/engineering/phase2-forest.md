# 第二阶段：近林拾柴原型

日期：2026-10-15。根据用户授权，Codex 接手工程、美术和体验验收。目标是先完成木屋与森林之间的短循环，再继续打磨表现。

2026-10-16 数值调整：用户试玩反馈采木过快，枯枝收益由 4 降至 2、倒木由 8 降至 4，仍各自按 20／45 秒恢复；手推车保持五倍收益，分别为 10／20。持续手动采集的长期平均从约 22.7 降至 11.3 木头/分钟，有车时从约 113.3 降至 56.7，接近原版的 10／50。既有库存与冷却不重置。下文保留初版实现和当时验收记录。

## 已实现的行为

- 沿用规则核心的森林解锁时机：陌生人到来后约 15 秒解锁，即首次生火后约 45 秒。游戏内可以直接点左侧木门出门，也能使用顶部地点导航；未解锁时没有出门热区。
- 森林使用本项目首批五张 PNG，按清单裁取并复用黑屋的 `mode` 像素缩小算法。枯枝、倒木、路标都是独立的透明场景热区，没有额外的常驻采集文字按钮。
- 枯枝一次获得 4 木头，20 秒恢复；从倒木收集断枝一次获得 8 木头，45 秒恢复。这是像素版近林原型的采集规则，独立于原始村庄的 `Outside.gatherWood()`，没有修改原有核心规则。
- 木头直接计入库存。采集后物件淡至 16% 透明度，下面细线显示恢复进度；悬停、键盘聚焦或点击时才显示提示。连续点击不会重复到账，两处独立恢复。
- 点左侧路标回屋，在炉膛直接添柴。森林中 F 不会远程操作屋内炉火。原有火力衰减、温度和建造者收入继续由同一个游戏时钟运行。
- 位置保存在 `game.pixel.location`，采集冷却复用核心的持久化 `cooldown`。导出／导入、刷新后保留地点和剩余冷却；返回木屋也不会清空采集冷却。没有这个字段的旧存档仍从木屋开始。
- 计时沿用已有策略：隐藏标签页期间补算；关闭再打开时恢复保存的剩余冷却，不以电脑墙钟计算离线产量。
- 开始界面、设置、事件和陌生人进门演出期间，场景热区不能采集或旅行。Tab、Enter 可操作，读屏描述随场景及采集状态变化；减少动态效果时停用森林飘雪。

## 窄屏

森林窄屏取景焦点为逻辑 x=240，已解锁森林的木屋为 x=224；未解锁时保持原取景。390×844 下门、炉膛、路标和两处采集物均在各自场景可用区域内。更窄窗口仍可使用顶部地点导航，完整构图和日志占比留待下一轮视觉打磨。

## 实现位置

| 文件 | 作用 |
| --- | --- |
| `src/app/forest.ts` | 旅行、独立采集规则、冷却、存档位置 |
| `src/pixel/forest.ts` | 读取原始素材、像素烘焙、森林合成、物件冷却状态 |
| `src/ui/scene-controls.ts` | 木门、路标、枯枝、倒木的透明按钮、上下文提示与恢复线 |

| `src/pixel/fit.ts` | 为每个场景指定窄屏取景焦点 |
| `tests/forest.test.ts` | 解锁、重复采集、往返、持久化、事件隔离、外出时炉火、窄屏区域 |

## 验证

- `npm run check`：类型检查通过，12 个测试文件、125 项测试通过。
- `npm run build`：通过，五张森林素材进入生产构建。
- 实际浏览器普通入口：点木门进入森林，点击枯枝、倒木，看到各一条采集记录；连续点击只产生一次收益。森林中 F 不添柴。刷新后仍在森林，并观察到倒木剩余恢复时间，而非重置成可拾取。
- 390×844 下实际点枯枝、点路标回屋、点炉膛添柴、再次点门出发。Tab 两次、Enter 成功采集枯枝。页面无横向溢出。
- 森林恢复后可以再次采集；事件锁定和外出炉火衰减有自动化回归。真实手机触摸、音频听感、长时间性能和全部事件未在本轮覆盖。
- 另从全新开局生火，未经调试、导入或刷新等待森林自然解锁；点门出发，两处采集后木头从 4 增至 16，重复点枯枝没有多领。点路标回屋并在炉膛添柴成功，之后处理自然出现的“噪声”事件。验收后导回体验前备份的原存档。

## 范围

当前只有近林拾柴。没有引入背包、移动人物、斧头、战斗、大地图或村庄建造界面。站立／行走人物仍保留先前占位状态。接下来的打磨以当前可玩的循环为基础，不需要先扩展地点。
