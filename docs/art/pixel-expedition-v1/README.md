## 两个镜头

世界：576 × 324 逻辑画幅，24 × 24 地块的俯视战略地图。镜头与聚落保持同类视角，村庄收为一个清晰地标，不画二十间独立住房。玩家脚底锚点固定，站位不能被树冠挡住；地标、地面、树木和迷雾分层。屏幕不足一个格的边沿可裁切，地图交互仍对应完整逻辑格。

战斗：576 × 324，侧向舞台。玩家脚底约 (144,250)，敌人约 (420,250)；屏幕上方预留标题/双方血条，中下部留动作信息，HTML 控件放画布外或稳定留白处。双方剪影和受击反馈保持清楚；不把大背景中的玩家或敌人烘焙进去。镜头只用于演出，实时战斗的命中/冷却始终由原核心决定。

| 敌人 | 4 种初级野外 + 5 个地点 ID | 详见映射；每个 ID 先一张清晰透明主姿态，攻击/受击用短位移和闪光验证，再决定增加帧数 |

### 敌人形象映射

| 原 ID | 形象要求与复用关系 |
| --- | --- |
| `snarling beast` | 低伏四足野兽，露齿但不夸张血腥；森林首个样片重点 |
| `beast` | 同类四足剪影的颜色/皮毛变体；仅复用造型，不合并场景数值 |
| `beastly matriarch` | 更粗壮的母兽、宽肩与伤疤；约 80 × 64，不能只是把普通野兽无差别放大 |
| `gaunt man` | 破衣枯瘦人形，避免将普通居民外观直接用于敌人 |
| `squatter` | 占屋者；与枯瘦人形共享人体基型，但衣物、站姿和持物区分 |
| `strange bird` | 长腿与尖喙，侧向冲刺剪影；约 48 × 56 |
| `two-headed creature` | 两颗头轮廓在实际显示尺寸都能分辨；约 80 × 64 |
| `cave lizard` | 贴地洞蜥，尾巴与头分开；约 64 × 40 |
| `lizard` | 洞蜥基型的更强壮变体，不通过缩放暗示固定生命值 |

这样是九个内容标识、约六类基础剪影，避免九套完整动作都从零生成。美术映射只决定外观，绝不能覆盖原版伤害、掉落或行为。

## 分批制作

1. **样片**：一块可平铺森林地面、村庄/洞口标识、主角俯视帧、森林战斗底图、玩家骨矛姿态与咆哮野兽。先在浏览器验证地图与战斗切换、缩放、血条和命中反馈，再铺开。
2. **初级野外**：补草地/荒地、两张背景、其余三种随机敌人及六枚道具图标。
3. **早期地点**：补废屋/铁矿/据点标识，岩壁/残墙/支架，五个地点敌人 ID 的变体和母兽。

不要将森林当作唯一可能出现的地形；也不要因为第一轮精修只覆盖周边，就删除其他原版地标。未精修分支的通用占位必须可辨认、有文本说明、可完成交互。

## 制作约束与验收

- 背景不含角色、敌人、UI、文字或固定战利品；物件要独立、可隐藏，避免同一对象出现两次。
- 精灵交付真实 RGBA，留出攻击位移与尾巴边界。阴影单独绘制或交给程序，不能带大片背景色。
- 多帧尺寸、人物身高与脚底锚点固定；按实际内容裁取，不假定生成图等分网格就是有效帧。
- 原图、提示词、原始尺寸、sourceRect、drawSize、锚点、帧序、SHA-256 分别记录。`planned-assets.json` 是工作单，不是加载器可用的已交付 manifest。
- 用既有像素采样方式与整数倍最近邻显示；至少在桌面 1280 × 720 和 1280 × 900 检查。透明图检查边缘，平铺图检查接缝；不以单张放大原画替代游戏内验收。
- 先以最少帧数证明攻击读得懂，再增加动作；不在当前阶段扩展手机适配、全武器换装、复杂寻路或全世界独立场景画。
