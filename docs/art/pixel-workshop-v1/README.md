# 木屋手推车与陷阱：素材与场景交互

日期：2026-10-15。用户要求取消人物头顶突兀的常驻“制作”，生成手推车和陷阱，并把物件和交互接入木屋。

## 最终行为

- 人物头顶不再常驻文字。鼠标悬停或键盘聚焦建造者时才显示“与建造者交谈”；顶部“制作”入口继续保留。
- 已制作的手推车停在左侧空地，木制笼式陷阱放在窗下。未制作时不显示；刷新、导入后依照已有数量恢复。多份陷阱以一件场景物件代表，在查看面板与读屏描述中显示实际数量。
- 点击手推车直接聚焦手推车详情，可选择“推车去森林拾柴”；点击陷阱直接聚焦陷阱详情，可选择“去森林检查陷阱”。出门后沿用已有拾柴收益、陷阱收获和冷却规则。
- 物件与其他精灵一同接受炉火和温度光照。文字只在悬停／聚焦时出现，空闲画面不常驻物件标签。
- 手机的扩大点击区域限制在画布内，避免拦截库存。画面缩小至每逻辑像素不足一个 CSS 像素、且已有陷阱时，人物入口由顶部按钮承担，避免和陷阱的点击区域重叠。
- 单件素材加载失败时不显示对应的透明场景按钮，制作面板仍可使用，不留下不可见的物件热区。

## 交付

- [原始素材与坐标清单](../../../assets/pixel/workshop/v1/README.md)
- [实际完整提示词](PROMPTS.md)：两次内置生成，均使用 transparent_background=true。
- `src/pixel/workshop.ts`：原图加载、像素烘焙、锚点与热区。
- `src/pixel/mapping.ts`、`renderer.ts`：制作数量到场景显示的映射，以及光照合成。
- `src/ui/hud.ts`：物件入口、详情聚焦和前往森林；`style.css`：悬停／聚焦提示。

## 验证

- 原图以 Pillow 只读检查了实际尺寸、alpha 和可见边界，并记录 SHA-256。自动化验证 PNG RGBA 格式、裁取范围、显示比例、逻辑热区隔离、320／390 宽度与 DPR 1／2／3 的点击区域不覆盖库存。
- `npm run check`：14 个测试文件、135 项测试通过；`npm run build`：通过，新素材进入生产构建。
- 在真实浏览器的独立生产预览（4174）中，以此前已经制作两件物品的试玩存档验收；没有覆盖用户开发入口（5174）的存档。
- 实际点击手推车／陷阱分别聚焦对应详情，再通过物件详情前往森林；从陷阱详情出发后检查陷阱，获得毛皮并进入 90 秒冷却。
- 刷新恢复后，两件物件依然显示；页面替代文本包含手推车及实际陷阱数量。
- 桌面空闲状态读取三处提示的计算样式，透明度均为 0，头顶没有常驻文字。
- 使用浏览器模拟 390×844、DPR 3，实际点击陷阱与键盘 Enter 操作手推车；面板正确聚焦，Esc 回到物件。物件热区底部不超过画布底部，页面宽度与滚动宽度均为 390。
- 浏览器警告／错误日志为 0；没有做真实手机触摸或音频听感验收。
